# 内部構造の改善

利用者から見える動作を変えずに内部構造を改善した場合、目的、変更内容、確認方法を日本語で記録します。

## 2026年9月10日: 日付処理とURL生成の共通化

- 目的: 機能ごとに重複していた処理を一元化する
- 変更内容: 日付解析、ページ名生成、プロジェクト検証、Scrapbox URL構築、月間予定本文生成を共有モジュールへ集約した
- 確認: 代表日、無効日、月境界、年境界、本文のエンコードを自動テストで確認した

## 2026年9月10日: JavaScript APIの文書化

- 目的: 共有APIの入力、出力、例外条件をソースコードから確認できるようにする
- 変更内容: `js/` 配下の主要APIとデータ構造へJSDocを追加した
- 確認: 全JavaScriptの構文チェックと自動テストを実施した

## 2026年9月10日: 文書構成と文書検査の整理

- 目的: 作業状態と変更履歴を分離し、各文書の用途を明確にする
- 変更内容: 文書索引と分類別の変更記録を追加し、文書リンクを検査するテストを新構成へ合わせた
- 確認: リポジトリ相対リンクと文書の存在を自動テストで確認した

## 2026年9月10日: 現行機能仕様の一元化

- 目的: 完了済み計画や旧Wikiに依存せず、現行機能と外部動作の正本を明確にする

- 確認: 仕様書が4アクション、エラーコード、互換エンドポイントを網羅することを自動テストで確認した
